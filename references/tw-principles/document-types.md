# 문서 유형 원칙

기술 문서는 독자의 목적에 따라 네 가지 유형으로 나눌 수 있어요. 리뷰할 문서가 어떤 유형인지 먼저 판단하고, 그 유형의 체크리스트를 기준으로 리뷰하세요.

| 문서 유형 | 독자의 목적 |
|---|---|
| **학습 중심 문서** | 새로운 기술/도구를 처음 접해서 흐름을 알고 싶을 때 (튜토리얼, 시작하기) |
| **문제 해결 문서** | 배경 지식이 있는 상태에서 특정 문제를 해결하고 싶을 때 (How-to, 트러블슈팅) |
| **참조 문서** | 이미 작동 방법을 아는 상태에서 특정 기능/API 사용법을 확인하고 싶을 때 |
| **설명 문서** | 개념, 원리, 배경 지식을 깊이 이해하고 싶을 때 |

문서 하나가 여러 유형의 요소를 결합할 수도 있어요 (예: 학습 문서 안에 개념 설명이 섞이는 경우).

## 1. 학습을 위한 문서

### 체크리스트

- 학습 목표를 명확하게 제시했는가?
- 처음부터 끝까지 막힘없이 따라 할 수 있는가? (모든 예제 코드가 실행 검증됐는가)
- 단계별로 설명되어 있는가? (간단한 예제 → 점진적으로 난이도 상승)
- 읽는 사람이 직접 실행할 수 있는 코드 예제가 포함되어 있는가?
- 문서가 길어지면 FAQ 섹션이나 접이식 컴포넌트로 부가 설명을 분리했는가?

## 2. 문제 해결을 위한 문서

### 체크리스트

- 단순히 에러 원인만 설명하는 게 아니라 기본적인 배경지식도 제공했는가?
- 즉시 적용할 수 있는 해결 방법이 포함되어 있는가?
- 환경별(운영체제, 라이브러리 버전 등) 차이를 고려한 설명이 있는가?
- (How-to 가이드) 특정 기능 구현에 초점을 맞췄는가? / (트러블슈팅) 이미 발생한 문제의 진단과 디버깅 과정에 초점을 맞췄는가?

## 3. 참조를 위한 문서

### 체크리스트

- 검색 및 탐색이 쉬운 구조인가? (목차, 앵커 링크)
- 정보가 정확하고 완전한가? 최신 상태인가?
- 문서가 일관된 구조와 형식으로 작성되어 있는가? (예: 함수 이름 → 매개변수 → 반환값 → 예제 코드)
- 실용적인 예시 코드가 포함되어 있는가?
- API 키 설정, 인증 방식처럼 독자가 사전에 알아야 할 핵심 정보가 문서 앞부분에 배치되어 있는가?

## 4. 깊은 이해를 위한 설명 문서

### 체크리스트

- 핵심 원리와 등장 배경이 명확하게 설명되었는가?
- 복잡한 개념을 다이어그램, 흐름도, 표 등으로 시각화했는가?
- 선행 지식이 충분히 안내되었는가?

## 유형별 템플릿

### 학습 중심 문서

```markdown
# [튜토리얼 제목]

## 목표
## 사전 요구사항
## 단계별 가이드
### [단계 제목]
### 최종 결과 확인
```

### 문제 해결 중심 문서

```markdown
# [문제 해결 문서 제목]

## 문제 정의
## 사전 요구사항
## 해결 방법
### [첫 번째 해결 방법]
### 문제 해결 후 확인 방법
```

### 참조 문서

```markdown
# [참조 문서 제목]

## 개요
## 속성 및 옵션
## 시그니처
## 반환 값
## 사용 예제
```

### 설명 문서

```markdown
# [개념명]

## 개념 소개
## 등장 배경
## 활용
```
