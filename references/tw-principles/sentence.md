# 문장 다듬기 원칙

기술 문서는 명확하고 이해하기 쉬워야 해요. 문서를 리뷰할 때 아래 다섯 가지 원칙을 기준으로 문장을 점검하세요.

## 1. 문장의 주체를 분명하게 하기

기술 문서를 읽는 독자는 주로 개발자이고, 문서에 적힌 작업을 직접 하는 것도 개발자예요. 따라서 **문서를 읽는 사람이 곧 행동의 주체**라는 걸 기준으로 삼으세요.

### 체크리스트

- 도구나 기술, 시스템을 행동의 주체로 사용하지 않았는가?
- 능동형으로 표현했는가?

### 예시

```diff
- 이 라이브러리는 데이터베이스 초기화를 수행해요.
+ 이 명령어를 실행하면 데이터베이스를 초기화할 수 있어요.

- 애플리케이션이 실행되기 전에 설정이 완료되어야 합니다.
+ 애플리케이션을 실행하기 전에 설정을 완료하세요.
```

다만 도구나 기술의 동작 자체를 설명할 때는 도구/기술이 주어가 될 수 있어요. (예: "Impression 로그는 두 가지 방식으로 동작해요.")

## 2. 필요한 정보만 남기기

문장을 짧고 간결하게 유지하고, 한 문장에는 하나의 생각만 담으세요.

### 체크리스트

- 문장이 짧고 간결한가? 한 문장에 여러 생각이 섞여있지 않은가?
- 메타 담화(말에 대한 말)를 최소화했는가? — 예: "다음으로", "앞서 설명했듯이", "사실은", "아시다시피" 같은 표현

### 예시

```diff
- 버튼을 클릭하면 다음 단계로 이동하게 되며, 그 이후의 작업을 진행할 수 있습니다.
+ 버튼을 클릭하면 다음 단계로 이동합니다. 이동 후 이어서 작업을 진행하세요.

- 아시다시피, 이 설정은 성능에 영향을 줍니다.
+ 이 설정은 성능에 영향을 줍니다.
```

## 3. 구체적으로 쓰기

모호하거나 장황한 표현은 독자의 이해를 방해해요. 직접적이고 구체적인 문장을 쓰세요.

### 체크리스트

- 명사 대신 동사를 사용했는가? (예: "설정 수행" → "설정")
- '가능성이 있다', '일부 경우', '필요할 수도 있다' 같은 모호한 표현 대신 확실한 정보를 제공했는가?
- 문장에서 누가, 무엇을, 어디에, 어떻게 하는지 생략된 정보 없이 다 썼는가?
- 실제 동작을 이해할 수 있는 표현을 썼는가? (업계 은어를 그대로 옮기지 않았는가)
- 모호한 수치나 기준(“많을 때”, “빠르게”) 대신 구체적인 수치를 제시했는가?
- 다른 문서/단락에서 참조하는 변수나 개념의 맥락(어디서 설명했는지, 어디서 쓰이는지)을 설명했는가?

### 예시

```diff
- 코드 최적화 진행 후 배포 수행이 필요합니다.
+ 코드를 최적화한 후 배포하세요.

- 설정 파일을 변경하면 기존 설정이 영향을 받을 수도 있습니다.
+ 설정 파일을 변경하면 기존 설정이 삭제됩니다.

- 파일을 업로드하면 자동으로 저장됩니다.
+ 사용자가 파일을 업로드하면 서버에 자동으로 저장됩니다.

- 데이터가 많을 때는 성능이 저하될 수 있습니다.
+ 데이터가 10,000건을 넘으면 응답 시간이 1초 이상 걸립니다.
```

## 4. 일관되게 쓰기

같은 개념을 여러 방식으로 표현하면 독자가 혼란을 느껴요.

### 체크리스트

- 공식 기술 용어(위키피디아/공식 문서 표기)를 따랐는가?
- 같은 개념을 하나의 표현으로 통일했는가?
- 약어는 처음 등장할 때 풀어쓰고 괄호로 병기했는가? (예: "SSR(Server-Side Rendering)")
- 외래어 표기는 업계에서 일반적으로 쓰이는 표현을 따랐는가?

### 예시

```diff
- K8을 사용하면 애플리케이션 배포가 쉬워집니다.
+ 쿠버네티스(Kubernetes)를 사용하면 애플리케이션 배포가 쉬워집니다.

- 이 기능은 SSR을 지원합니다.
+ 이 기능은 SSR(Server-Side Rendering)을 지원합니다.
```

## 5. 자연스러운 한국어 표현 쓰기

불필요한 한자어, 번역체 표현을 줄이면 문장이 더 직관적이에요.

### 체크리스트

- '수행하다', '실행하다', '진행하다' 같은 불필요한 한자어를 뺐는가?
- 영어식 명사형 표현('-tion', '-ing', '-ment')을 한국어 동사 중심으로 자연스럽게 바꿨는가?

### 예시

```diff
- 로그 파일을 삭제하는 작업을 수행합니다.
+ 로그 파일을 삭제합니다.

- API 키를 이용한 사용자 인증 처리가 완료된 후, 데이터베이스 접속 설정 진행이 가능합니다.
+ API 키로 사용자를 인증한 후, 데이터베이스에 접속하도록 설정할 수 있습니다.
```
